# claude-session-title 设计

复刻自 [oil-oil/oil-codex-title](https://github.com/oil-oil/oil-codex-title)（MIT），把「每轮结束后用独立模型维护话题标题」移植到 Claude Desktop（Code 标签页）与 Claude Code。

## 目标与非目标

目标：每轮对话后在后台生成「类别 emoji + 对象｜目标」标题，写入 Desktop 侧边栏；不向对话追加任何消息；标题准确时保持不变。

非目标（第一版不做）：闲置归档、用量账本、批量改历史会话、重名检测、独立 Skill。

反目标：不直接改写 Desktop 的 `local_*.json` 或会话 transcript（私有状态）；不让主模型调用改名工具；不在测试里调用真实模型。

## 为什么是这个形态（实测依据）

| 事实 | 证据 |
| --- | --- |
| Stop 事件不认 `sessionTitle`，只有 `UserPromptSubmit` 和 `SessionStart` 认 | Claude Code 2.1.317 二进制 |
| `sessionTitle` 只改 CLI 自己的标题，Desktop 侧边栏不采纳 | Desktop 日志无 `updateSession`；`title` 不变 |
| `mcp_tool` hook 可直接调 Desktop 的 `ccd_session_mgmt.set_session_title`，Desktop 采纳 | transcript 与 Desktop 日志 |
| `mcp_tool` 的 `input` 只能用 `${path}` 引用 hook 输入；`UserPromptSubmit` 输入含 `session_title` | 二进制 + 日志 |
| Stop hook 内可调 `claude -p --model haiku` | 两种环境均成功 |

## 流程

1. **Stop（异步命令）**：读 transcript 最近几轮，调 Haiku 生成候选，校验后存为 pending。
2. **UserPromptSubmit（同步命令）**：有 pending 且未锁定，返回 `sessionTitle`，CLI 标题变为新标题。
3. **UserPromptSubmit（mcp_tool）**：`set_session_title(self, "${session_title}")`，把 CLI 标题转给 Desktop。

滞后：第 N 轮后算出的标题，CLI 在第 N+1 条消息时更新，Desktop 在第 N+2 条消息时显示。这是已知取舍。

## 保护规则

- 以 `session_title` 与上次写入值比较发现手动改名，发现即锁定该会话。首次写入前没有基线，不判定手动改名。
- 暂停（全局）、锁定（单会话）时不写入，也不调用模型。
- 写入前再次读取最新状态；会话已有新内容或被锁定则丢弃候选。
- 纯确认（“好的”“继续”等）且基线一致时免调模型，最多连续两轮。
- 同一会话用内核文件锁；模型子进程带环境守卫并禁用 hook，避免递归。
- 校验：恰好一个「｜」、一个允许的类别 emoji、长度 ≤48、无控制字符、路径、链接、邮箱等。

## 组成

- `prompts/naming.md`：命名提示词，来自原版，去掉 Codex 专有内容。
- `scripts/title_core.py`：纯逻辑（transcript 解析、摘录、校验、确认判断）。
- `scripts/claude_title.py`：hook 入口与管理命令（`stop`、`prompt`、`install`、`uninstall`、`status`、`pause`、`resume`、`lock`、`unlock`、`doctor`）。
- `scripts/file_lock.py`：跨平台内核锁，来自原版。
- 数据目录 `~/.claude/claude-session-title/`（可用 `CLAUDE_SESSION_TITLE_DATA` 覆盖）。

## 我替你做的决定（可推翻）

- 项目名 `claude-session-title`；Python 3.10+，只用标准库，测试用 `unittest`。
- 安装方式：`install` 把 hook 写入用户级 `~/.claude/settings.json`，写前备份；不做 Claude Code 插件包（插件内 `mcp_tool` 可能被限制调用插件自带 MCP，未验证）。
- 默认命名模型 `haiku`，依赖 PATH 上已登录的 `claude`。

## 已知限制（未验证项）

- 每个新会话第一条消息，`mcp_tool` hook 因 `session_title` 为空会报一条非阻塞错误，界面表现未验证。
- 手动改名（已验证）：Desktop 把手动改名同步给 CLI（transcript 出现 `custom-title`）；`set_session_title` 对相同标题返回 already named，不回滚、不改名；插件检测到与 `last_applied_title` 不同，锁定会话。
- 未验证：本工具第一次写入前就手动改过名的会话（无基线，pending 可能覆盖，且 `set_session_title` 可能对用户设置的标题弹确认）；缓解办法是先 `lock`。
- 端到端（新会话装真实 hook，3 条消息后 Desktop 标题被正确改写）与手动改名场景均已在 2026-11-06 真机验证。
- 用户级安装（`~/.claude/settings.json`）后，在真实 Desktop 会话上再次验证：第 N 轮结束生成 pending → 第 N+1 条消息写入 CLI → 第 N+2 条消息 Desktop 标题变为新标题（`titleSource: tool`），期间无拒绝、无报错。
- `mcp_tool` 首次运行会把同一标题“重设”一次（返回 `Renamed … (was …)`），使 `auto` 来源的会话转为 `tool` 来源；因此无法单独观察纯 `auto` 来源下的行为，但转换本身没有触发确认或错误。
- 终端里的 Claude Code 没有 `ccd_session_mgmt`，mcp hook 每条消息会报非阻塞错误。
- 依赖的 Claude Code 内部行为来自 2.1.317 的二进制，版本升级可能变化。
